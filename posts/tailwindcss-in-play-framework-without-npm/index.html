TailwindCSS in Play Framework - Without npm

A Guide on how to use and automate TailwindCSS compilation in a Play app with an sbt-web source file task. No need for npm, complicated bundlers or Javascript.

August 18, 2024
4 minutes
Michael Hertig
dev guide playframework

Introduction

I am not a fan of the Javascript ecosystem, and I have come to the point where I almost always prefer solutions that work without it. Here is my issue though: I quite like Tailwind CSS. In my Play Framework stack I'm only using tools that do not require me to configure a complex javascript bundler, don't have thousands of npm dependencies, and don't need a dozen different build steps.

Fortunately, the Tailwind CSS compiler is also available as a standalone CLI, so it doesn't have to be installed via npm. Using the CLI, we can easily integrate TailwindCSS into a Play Framework project by just calling the CLI as part of a sbt-web source file task.

You can find an example project for this guide here: https://codeberg.org/hertg/play-tailwindcss

Add sbt-web

If your project doesn't already use sbt-web, make sure to enable it.

// ./build.sbt

lazy val root = (project in file("."))
  .enablePlugins(PlayJava, SbtWeb)

Download the CLI binaries

Go to the latest Tailwind release and download the pre-compiled binaries. Place the downloaded binaries in the root directory of your project, and make sure that the files are executable; for example on Linux:

chmod +x ./tailwindcss-linux-x64

I'd recommend downloading the binaries for all architectures and operating systems where you wish your project should be able to build on. In this guide I only include support for Linux and Windows on x64, but adding support for others (e.g., arm and macos) can easily be added later.

Create helper method to run commands

Add a file called CommandRunUtil.scala to your project/ folder. This will provide a simple runCommand method for us to use in the sbt source task.

// ./project/CommandRunUtil.scala

import sbt.*

import java.io.IOException
import scala.sys.process.Process

object CommandRunUtil {

  lazy val isWindows: Boolean = System.getProperty("os.name").startsWith("Windows")

  /**
   * Utility method to run a command
   *
   * @param command          The command to execute (eg. "npm")
   * @param args             The command line arguments (eg. "--test --build")
   * @param detached         Whether it should run concurrently (true) or block the next tasks
   * @param workingDirectory The working directory to execute the command
   * @param logger           The logger to use for output
   * @return The process running the given command
   */
  def runCommand(command: String,
                 args: List[String] = List.empty,
                 detached: Boolean = false,
                 workingDirectory: File,
                 logger: Logger): Process = {

    // The full command which will be executed (adapted to run on Unix and Windows)
    val fullCommand: scala.collection.Seq[String] = if (isWindows) {
      "cmd" :: "/c" :: command :: args
    } else {
      command :: args
    }

    logger.info(s"Running command (detached: $detached) '${fullCommand.mkString(" ")}'")

    // Instantiate the process
    val process = Process(fullCommand, workingDirectory)
    // Run the process with the given logger to use as stdout
    val startedProcess = process.run(logger)
    // If the process should NOT run detached and exits with an error, throw an exception
    if (!detached && startedProcess.exitValue() != 0) {
      throw new IOException(s"command '${fullCommand.mkString(" ")}' failed with exit code ${startedProcess.exitValue()}")
    }

    // Return the process
    startedProcess
  }
}

Create an sbt source task

Add a file called tailwind.sbt as a sibling of your build.sbt to your project's root directory.

// ./tailwind.sbt

import com.typesafe.sbt.web.Import.WebKeys.webTarget
import sbt.io.Path.relativeTo

val tailwindSourceTask = taskKey[Seq[File]]("Tailwind CSS source file task")
tailwindSourceTask := {
  val logger = streams.value.log
  logger.info("running tailwind source task")
  val start = System.nanoTime()
  val sourceDir = (Assets / sourceDirectory).value / "tailwind"
  val workingDir = baseDirectory.value

  val targetDir = webTarget.value / "tailwind-plugin"
  val sources = sourceDir ** "*.css"
  val mappings = sources pair relativeTo(sourceDir)
  val compiled = mappings map { case (file, path) => file -> (Assets / resourceManaged).value / path }

  // note: add support for other OS and non x64 here,
  // the 'cmd' variable should simply resolve to the name 
  // of the binary to use
  val cmd = CommandRunUtil.isWindows match {
    case true => "tailwindcss-windows-x64.exe"
    case false => "tailwindcss-linux-x64"
  }
  compiled.foreach { case (f, p) =>
    val args = List("-i", f.absolutePath, "-o", p.absolutePath, "--minify")
    CommandRunUtil.runCommand(s"./$cmd", args, detached = false, workingDir, logger)
  }

  val result = compiled map (_._2)
  val took = (System.nanoTime() - start) / 1000 / 1000
  logger.info(s"finished tailwind source task (${took}ms)")
  logger.debug(s"result: $result")
  result
}
Assets / sourceGenerators += tailwindSourceTask.taskValue
You can find more information about source file tasks in the README of the sbt-web project.

Create the tailwind config

In the root directory of your project, create a file tailwind.config.js. This is where you'll be able to configure TailwindCSS.

// ./tailwind.config.js

/** @type {import('tailwindcss').Config} */
module.exports = {
    content: [
        "./app/**/*.scala.html",
    ],
    theme: {},
    plugins: [],
}

Make sure to include a glob that includes all your Twirl views. TailwindCSS will search the locations configured for uses of tailwind css classes, so that the compiled css file only includes the directives you actually need.

Create the tailwind.css file

Create a file tailwind/tailwind.css in the assets directory of your project. By default this will be ./app/assets/.

/* ./app/assets/tailwind/tailwind.css */

@tailwind base;
@tailwind components;
@tailwind utilities;

/*
If you want to add your own default base styles for specific HTML elements,
use the @layer directive to add those styles to Tailwind’s base layer:
*/
@layer base {

}

/*
Use the components layer for any more complicated classes you want to add to
your project that you’d still like to be able to override with utility classes.

Traditionally these would be classes like card, btn, badge — that kind of thing.
*/
@layer components {

}

/*
Add any of your own custom utility classes to Tailwind’s utilities layer:
*/
@layer utilities {

}

This is where you can define base styles, components, and utility classes that will be available in all your views.

Include in HTML

The last step is to include the generated tailwind stylesheet inside the <head> section of your HTML.

<head>
    ...
    <link rel="stylesheet" href="@assetsFinder.path("tailwind.css")" />
    ...
</head>

Directory Structure

For reference, here is what the directory structure of your project should look like after finishing this guide:

your-project/
├── app/
|   ├── assets/
|   |   └── tailwind/
|   |       └── tailwind.css
|   └── ...
├── conf/
├── project/
|   └── RunCommandUtil.scala
├── build.sbt
├── tailwind.config.js
├── tailwind.sbt
├── tailwindcss-linux-x64
└── tailwindcss-windows-x64.exe

That's it

That is everything you need. With all those steps applied, TailwindCSS will be compiled automatically in dev-mode, as well as when you compile your project for production, no further steps are necessary.

Please note that due to how we downloaded the CLI binaries, you will not receive any automated updates for Tailwind. If you want to use the latest features, and if you want to keep up-to-date with security patches for the Tailwind CLI, you should frequently update the binaries manually, or write a script or CI that updates the binaries for you. If you happen to implement an automatic update like that, hit me up on Mastodon or via Email, so that I can update this guide.
